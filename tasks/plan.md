# План: Claudian Schedule — отложенные сообщения

## Зачем

Написать сообщение сейчас, а Клодиан отправит его себе в чат в назначенное время.
Пример: в 23:00 задать «в 6:00 собери, что горит по проектам» — утром ответ уже есть.

## Решения владельца (24.09.2026)

| Вопрос | Решение |
|---|---|
| Обсидиан был закрыт в назначенное время | Отправить при первом запуске, если опоздание < 12 часов; больше — пометить «просрочено» и показать |
| Повторяющиеся (каждый день в 9:00) | Пока НЕ делаем. Только разовые |
| Куда класть по умолчанию | В открытую сейчас вкладку; при создании можно выбрать новую |

## Архитектурные решения

1. **Отдельный плагин, не правка Клодиана.** Клодиан — чужой плагин (Yishen Tu), обновляется через BRAT;
   правки затрутся при обновлении. Свой плагин переживает обновления Клодиана.
2. **Стык через интерфейс (DOM), как в Claudian Voice.** Опорные точки те же, что уже проверены
   голосовым плагином: `textarea.claudian-input`, `.claudian-tab-badge-streaming`, `.claudian-message-user`.
   Отдельного программного входа у Клодиана нет (в коде только 6 команд, ни одна не отправляет текст).
3. **Проверка исхода, а не попытки** (§🎯 v2.85, §👁 v3.16): отправка считается удачной, только если
   поле ввода опустело И в переписке появилось новое сообщение от пользователя. Нажатие Enter — не доказательство.
4. **Черновик владельца неприкосновенен.** Если в поле ввода уже что-то набрано — отложенное сообщение
   уходит в новую вкладку, набранное не трогаем.
5. **Агент занят — ждём, потом новая вкладка.** Пока идёт ответ, не встреваем; если занят дольше
   настроенного времени — открываем новую вкладку (там он свободен).
6. **Хранение — в data.json плагина.** Папка `.obsidian/` в игноре git хранилища (проверено 24.09),
   значит на devbox не уедет и дважды не выстрелит.
7. **Журнал `schedule.log`** рядом с плагином — чтобы разбирать «почему не ушло» по факту, а не по памяти.

## Ограничение, которое честно сказать владельцу

Плагин живёт внутри Обсидиана. **Обсидиан закрыт — никто ничего не отправит.** Спящий Мак: таймер
не тикает во сне, но при пробуждении срабатывает проверка просрочки и сообщение уходит (в пределах 12 часов).

## Задачи

### Фаза 1. Основание

**Задача 1: Разбор времени и формат показа (XS, 1 файл)**
- Описание: чистые функции `parseWhen`, `formatWhen`, `humanLeft`, `decideOverdue` — без Обсидиана.
- Критерии приёмки:
  - [ ] Понимает: «через 30 минут», «через 2 часа», «сегодня 18:00», «завтра 9:00», «24.09 18:30», «18:00», «2026-09-24 18:30»
  - [ ] «18:00», когда уже 19:00 → завтра, не в прошлое
  - [ ] Мусор → внятная ошибка по-русски, не молчаливый ноль (§🤐 v3.35)
- Проверка: `node test/when.test.js` — зелёный; в тестах есть случай «время в прошлом»
- Зависимости: нет

**Задача 2: Хранение и планировщик (S, 1 файл)**
- Описание: список сообщений в data.json, тик раз в 20 секунд, проверка просрочки при запуске.
- Критерии приёмки:
  - [ ] Сообщение с наступившим временем берётся в работу ровно один раз
  - [ ] При запуске опоздание < 12 ч → отправляем; ≥ 12 ч → статус «просрочено» + уведомление
  - [ ] Статусы: ждёт / отправлено / просрочено / не удалось
- Проверка: `node test/overdue.test.js`; учение — подложить в data.json время в прошлом
- Зависимости: 1

### Контрольная точка A
- [ ] Тесты зелёные, `node --check main.js` без ошибок

### Фаза 2. Доставка

**Задача 3: Доставка в Клодиан + проверка исхода (M, 2 файла)**
- Описание: найти поле ввода, при необходимости открыть окно/новую вкладку, вставить текст, отправить,
  **убедиться, что сообщение появилось в переписке**.
- Критерии приёмки:
  - [ ] Окно Клодиана закрыто → открывается само
  - [ ] Агент печатает → ждём, не встреваем
  - [ ] В поле есть черновик → он не тронут, сообщение ушло в новую вкладку
  - [ ] Не удалось → статус «не удалось» + причина в журнале и уведомлении
- Проверка: `node test/deliver.test.js` на **настоящем** дереве страницы (jsdom), а не на своей заглушке (§🧫 v3.34)
- Зависимости: 2

**Задача 5: Список и управление (S, 2 файла)** — что в очереди, отправить сейчас, перенести, удалить, история.

### Контрольная точка C — живая проверка
- [ ] Установка, перезапуск Обсидиана
- [ ] Запланировать сообщение через 2 минуты → оно приходит в чат само
- [ ] Убедиться глазами: в переписке новое сообщение, в журнале строка «отправлено»

## Риски

| Риск | Влияние | Что делаем |
|---|---|---|
| Обновление Клодиана переименует классы в интерфейсе | Высокое | Одно место поиска (`bridge`), при отказе — внятное сообщение и запись в журнал, а не тишина |
| Сообщение уйдёт посреди чужого разговора | Среднее | Уходит в новую вкладку, если поле занято черновиком или агент долго занят |
| Двойная отправка при двух окнах Обсидиана | Среднее | Отметка «взято в работу» + запись `sentAt` до отправки; `.obsidian/` не синхронизируется |
| Ночная отправка разбудит уведомлением | Низкое | Уведомления можно выключить в настройках |

## Открытые вопросы

- Повторяющиеся сообщения — решено отложить, вернёмся, если приживётся.
